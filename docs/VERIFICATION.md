## Per-claim findings

**`workflow-selector-three-domains` — HOLD (high).** All three `--fake --episodes 60` examples print the
claimed best arm with pulls concentrated there. The offline fakes were read and confirmed **honest**: the
code reward runs the real subprocess executor (10/10 reference impls pass, 10/10 buggy fail) and the fake
routes by *prompt step*, not arm identity; the search reward is real grep-vs-gold with file choices
validated against actual hits (corpus excludes `domains/` so keyword tables can't leak); the compaction
reader returns gold only if the fact-bearing line survived, keyed on content not strategy name. The bandit
sees only scalar rewards. **Limitation:** search's iterative (0.90) and broad_then_narrow (0.85) are
near-tied, so 3/20 seeds settle on broad_then_narrow (still beats 1/3 at 0.83–0.88); compaction has 1/20
seeds (seed 19) where ε-greedy locks onto extractive at acc 0.383, *below* the 0.519 uniform-arm baseline.
Textbook small-sample lock-in, not rigging — but real failure cases, so "selects the best arm" is
modal/mean-true, not universal.

**`contextual-linucb-beats-average-case` — HOLD (high).** LinUCB reaches exactly 1.000 tail accuracy on all
10 seeds while average-case bandits plateau at ~0.50 (the real ceiling for a 50/50 split). The win is shown
to come from informative context, not the code path: a constant `[1,1]` featurizer, or features keyed on
`id%2` (uncorrelated with type), both collapse LinUCB to ~0.42–0.59. Features encode only `task['type']`
(a legitimate pre-action observable); no reward/gold leakage. **Limitation:** the task is synthetic (typed
arms) — an honest stand-in, not a real workload.

**`rl_multihop_reinforce` — HOLD (high).** Example + unittest reproduce the headline numbers exactly (4/4
pass). No-leakage evidence: zeroing the noisy signal feature collapses RL to exactly 0.357 (the fixed cap),
proving position features don't leak depth; a signal stress test (noise 0.0 → 1.0, noise 0.5 → 0.29 ≈
random) confirms success tracks signal reliability with no hidden channel. The REINFORCE update was verified
as a true score-function gradient (analytic vs numerical match 2e-10) with an unbiased running-mean
baseline. **Limitation:** "~0.81" is the seed-0 point; honest cross-seed range is ~0.80–0.85. The "provably
capped at 1/3" statement is exactly correct for the fixed-horizon family (a stronger signal-greedy heuristic
reaches 0.73, which REINFORCE still beats).

**`bird_sql_bandit_real_run` — HOLD (high).** Every README Results number was recomputed from
`logs/exp_*.jsonl` with the repo's own `src/metrics.py` and reproduced. Adversarial re-execution of
`compute_reward` on 40 sampled logged (generated_sql, gold_sql) pairs against the real BIRD SQLite DBs found
**0 mismatches** — rewards are genuine execution-match, not fabricated. Gold SQL is never passed to the LLM;
the oracle is a fair per-task max over single-arm rewards. **Limitation (the most honest weakness in the
report):** the bandit-vs-random win is mean-only (+2.0) and holds in just **2/3 seeds** — in seed 0 the
bandit (21) *loses* to random (23). With 3 seeds and a ~2-point margin there is no statistical significance
over random, and the README correctly claims none; the durable result is learning online to down-weight the
weak decompose arm (true in all 3 seeds). The two top arms are statistically tied (overlapping Wilson CIs).

**`cross-domain-sweep` — HOLD (high).** A canonical re-run regenerated `results/sweep.json`
byte-identically. Best policy per domain (code 1.00 / search 0.867 / compaction 0.667) sits far above 1/3;
robust across seed sets 5–7 and 10–14. All three domains compute real rewards. **Limitation:** the literal
"1/3 random baseline" is a *weak* bar — the true uniform-over-arms baseline is higher (0.70/0.82/0.53). The
claim is true but understates the result; the stronger honest finding is that the bandits concentrate on
the best arm and beat the uniform-arm baseline (clearest in compaction: ~0.63–0.67 learned vs 0.53 uniform).

## Limitations & honest caveats (aggregated)

- **Small-sample bandit lock-in is real, not hypothetical.** 3/20 search seeds settle on the near-tied arm;
  **1/20 compaction seeds (seed 19) lock onto a worse-than-random arm** (0.383 < 0.519). Default seed 0 is
  modal/representative, not cherry-picked, but "always selects the best arm" is not universal.
- **The BIRD headline win is weak in significance.** Bandit beats random by mean +2.0 but only in 2/3 seeds,
  and **loses in seed 0**. No significance is claimed (correctly); the durable result is online avoidance of
  the weak `decompose` arm.
- **Two synthetic tasks are honest stand-ins, not real workloads.** `contextual-linucb` (typed arms) and
  `rl_multihop` (depth/signal env) are designed tasks — stress-tested to rule out leakage, but illustrative.
- **The 1/3 random baseline is a soft bar** for the domain sweeps (true uniform-arm baseline 0.70/0.82/0.53).
- **No rigging, gold-leakage, fabricated results, or unfair baselines were found in any claim.** By-design
  differentiation in the offline fakes is acceptable because every reward is computed from the arm's actual
  output (real subprocess / grep / fact-retention), never hardcoded by arm name, and the policies see only
  scalar rewards.
